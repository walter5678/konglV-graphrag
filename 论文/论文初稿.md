# 基于知识图谱增强检索生成的低空经济无人机法律智能问答系统研究

## 摘要

随着低空经济快速发展，无人驾驶航空器在物流配送、农业作业、测绘巡检、应急救援和公共治理等场景中的应用不断扩大。与此同时，相关法律法规、部门规章、技术标准、地方性法规及司法案例数量持续增长，法律文本之间存在引用、适用、修订、废止、上下位法和违法后果等复杂关系。传统关键词检索难以准确处理法律概念的语义变化，纯向量检索又容易忽略法规效力、条款关联和时效性，导致检索结果不完整或引用失效依据。为解决上述问题，本文设计并实现了一种基于知识图谱增强检索生成（GraphRAG）的低空经济无人机法律智能问答系统。

本文首先构建面向无人机法律领域的领域本体，将法规、章/节、条款、术语、无人机分类、义务主体、活动场景、法律后果和司法案例等纳入统一知识模型；然后采用“结构化分段—实体与关系抽取—实体归一与知识融合—图数据库存储”的流程构建法律知识图谱。在问答阶段，系统融合BGE-M3稠密检索、BM25稀疏检索、RRF结果融合、bge-reranker精排和Neo4j多跳图扩展，并通过现行有效过滤、来源溯源和引用约束控制答案风险。系统已形成包含107部法规、531个司法案例、6650个节点和12489条关系的知识图谱，并以36道覆盖13类考点的测试集开展检索和生成评测。结果表明，稠密检索配置的Hit@5为0.722，混合检索结合精排和图扩展配置的综合答案质量为0.908，引用正确性为0.950，时效性为0.947。实验同时发现，实名登记、法规版本和机型阈值等陷阱问题仍是系统的主要薄弱环节。

**关键词：** 低空经济；无人驾驶航空器；知识图谱；GraphRAG；法律智能问答；时效性检索

## 1 引言

### 1.1 研究背景

低空经济是以低空空域为主要活动空间，以通用航空、无人驾驶航空器和相关基础设施、服务体系为重要组成部分的新兴经济形态。无人机应用具有主体多元、活动类型复杂、空域限制明显和法律责任链条较长等特点。同一问题往往需要同时判断无人机类型、飞行活动性质、运行空域、操控人员资格、运营资质、实名登记、适航要求和违法后果。

无人机法律规范并非集中于单一法律文本，而是分布在民用航空、空域管理、无线电管理、测绘、数据安全、个人信息保护、治安管理、地方低空经济促进以及行业标准等多个规范层级。不同法规之间还存在“上位法—下位法”“一般规定—特别规定”“旧法—新法”“条款—引用条款”等关系。例如，针对同一行为，国家行政法规可能规定基本义务，部门规章进一步细化运行条件，地方性法规则结合本地空域和产业发展作出补充规定。问答系统如果只依据文本相似度返回片段，容易出现依据失效、条款遗漏、主体混淆和罚则错配等问题。

### 1.2 研究问题

本文重点解决以下问题：

1. 如何将分散、异构且具有法律效力层级的无人机规范文本转换为可计算的知识结构；
2. 如何表示法规之间的引用、适用、主体义务、违法行为与法律后果关系；
3. 如何在检索过程中同时利用语义相似性、关键词匹配、图结构关联和法规时效性；
4. 如何约束大语言模型仅依据可追溯条款生成答案，降低法律问答中的幻觉风险；
5. 如何通过可复现的检索和生成评测验证系统效果，并定位时效性和机型陷阱问题。

### 1.3 主要贡献

本文的主要工作包括：

（1）提出面向低空经济无人机法律问答的领域本体，将法规、条款、术语、机型、主体、活动、法律后果和案例统一纳入图谱；

（2）设计“规则与大语言模型协同”的知识构建流程，在保留条款原文和来源信息的基础上抽取实体、属性、关系和法律事件；

（3）构建融合稠密检索、稀疏检索、重排、图扩展及时效过滤的GraphRAG问答链路；

（4）建立包含36道问题的评测集，分别从检索命中、召回、排序、忠实度、正确性、时效性和引用正确性等维度开展实验；

（5）总结当前系统在实名登记、法规版本和机型分类问题上的失效模式，为法律智能问答系统的后续优化提供依据。

## 2 相关技术与研究基础

### 2.1 知识图谱

知识图谱通常以实体、关系和属性为基本组成部分，以图结构表达现实世界中的对象及其关联。对于法律领域，知识图谱不仅要表示“法规—条款—概念”之间的结构，还要记录规范的适用条件、行为主体、法律后果、发布日期、生效日期、失效状态和来源证据。因此，法律知识图谱更接近带有时态、层级和证据属性的多关系异构图。

### 2.2 检索增强生成

检索增强生成通过先检索外部知识，再将检索结果提供给生成模型，从而减少模型仅凭参数记忆作答造成的事实错误。在法律问答中，检索单元应尽量与法条边界一致，并保留法规名称、条号、正文和时效元数据。与普通RAG相比，GraphRAG进一步利用实体关系和图结构扩展检索上下文，适用于需要跨条款、多跳关联和法规体系概览的问题。

### 2.3 混合检索与重排

稀疏检索擅长匹配法规名称、条号、专有术语和罚款金额等精确词项；稠密检索擅长处理口语化表达、同义改写和跨表述语义匹配。系统采用BGE-M3生成文本向量，使用BM25进行关键词检索，再利用RRF进行结果融合。候选结果经bge-reranker-v2-m3重排后进入图扩展和生成阶段。

### 2.4 大语言模型结构化抽取

大语言模型能够从复杂条款中抽取义务主体、适用条件、行为、法律后果和引用依据，但存在关系漂移、数字错误和无依据补全等风险。因此，本文采用本体约束、JSON结构校验、受控词表、规则复核和原文证据绑定等机制，避免将模型生成内容直接作为无条件事实写入图谱。

## 3 系统需求与总体架构

### 3.1 领域需求分析

无人机法律问答具有以下特点：

（1）**规范层级多。** 法律、行政法规、部门规章、地方性法规、规范性文件和国家标准可能同时影响同一问题；

（2）**关系依赖强。** 问题通常需要沿着“机型—活动—空域—许可—义务—罚则”路径综合判断；

（3）**时效敏感。** 已废止、已修改、尚未生效的条款不能与现行依据等量处理；

（4）**证据要求高。** 回答应给出法规名称、条号和必要的原文证据；

（5）**问法灵活。** 用户可能使用“黑飞”“小飞机”“需要办什么手续”等非法律术语，系统需要进行概念归一和语义匹配。

### 3.2 总体架构

系统采用六层架构：

```text
应用层：Web问答界面、引用展示、图谱可视化
生成层：大语言模型回答、法条引用、时效提示
检索层：稠密检索、BM25、RRF、重排、图多跳扩展
存储层：Neo4j图数据库、Chroma向量库、元数据索引
图谱层：结构化分段、实体关系抽取、实体对齐、知识融合
数据层：法规、标准、规范性文件、司法案例与官方解读
```

系统将条款作为核心检索单元。每个条款单元具有唯一`unit_id`，同时作为知识图谱中的Article节点和向量库中的父文档标识，从而保证检索结果、图谱节点和最终引用之间的一致性。

### 3.3 问答处理流程

```text
用户问题
  ↓
问题预处理与实体识别
  ↓
BGE-M3稠密检索 + BM25稀疏检索
  ↓
RRF融合与现行有效过滤
  ↓
bge-reranker精排
  ↓
Neo4j图多跳扩展
  ↓
构造带来源上下文
  ↓
LLM生成带条号引用的答案
  ↓
引用、时效与格式校验
```

## 4 法律知识图谱构建方法

### 4.1 数据来源与预处理

系统整合三类数据来源：已有结构化法规条款、官方或权威渠道采集的法规原文，以及北大法宝司法案例和法规资料。预处理阶段完成HTML/PDF文本解析、标题和条款识别、章节层级恢复、来源字段保留、跨源去重和元数据归一。

现有结构化阶段形成3701个条款或语义单元，覆盖132部法规；建图阶段进一步形成107部法规节点、3522个Article节点和531个Case节点。对于扫描版标准和格式不稳定的PDF，应通过OCR、人工核验或权威可复制版本进行补录，不能把低质量识别结果直接作为法律依据。

### 4.2 本体设计

系统设计了九类主要节点：

| 节点类型 | 典型内容 |
|---|---|
| Regulation | 法规名称、效力层级、发布机关、生效日期、时效性 |
| Article | 条号、条文、章、节、来源、效力信息 |
| Section | 章、节及其标题和序号 |
| Term | 法律术语、定义和别名 |
| DroneCategory | 微型、轻型、小型、中型、大型及阈值 |
| Actor | 操控员、运营人、民航管理部门、公安机关等 |
| Activity | 实名登记、适航、经营性飞行、测绘飞行等 |
| Sanction | 罚款、责令改正、没收、吊销许可等 |
| Case | 案号、法院、案由、判决摘要和援引法条 |

系统设置“属于、引用、上位法依据、废止/取代、定义、适用于、义务主体、违反后果、案例援引法条”等关系。结构归属关系主要由元数据直接生成；引用关系由正则表达式和模型联合识别；适用、义务主体和违法后果关系则主要依赖受控词表与大语言模型抽取。

### 4.3 条款结构化

条款结构化遵循“一条一单元”的原则：一条法条通常对应一个Article节点和一个向量父文档。对于长条文，不简单截断，而是保留款项结构；对于没有明确“第X条”格式的材料，按语义窗口切分并标记为语义段。条文正文与Embedding前缀分离：图谱保存纯净原文，向量化时再补充法规名称和条号，以便后续引用和规则解析。

每个条款单元至少保存以下信息：

```text
unit_id、law_id、法规名、效力层级、发布机关、文号
公布日期、生效日期、时效性、来源、章、节、条号、条文
```

### 4.4 实体、关系和事件抽取

对于法规名称、条号、日期、金额和固定规范词，系统使用正则表达式、词典和规则进行高置信抽取；对于“谁应当做什么”“在什么条件下适用于哪类无人机”“违反后承担何种责任”等复杂语义，采用大语言模型输出受控JSON。

法律事件采用“主体—行为—条件—对象—机关—后果—依据”的结构表示。例如“未经批准在管制空域飞行”可抽取为：行为主体为操控者，行为为管制空域飞行，条件为未经批准，活动类型为飞行活动，法律后果为责令停止或罚款，依据为对应罚则条款。相比单一三元组，事件结构更适合表达带条件和多后果的法律规范。

### 4.5 实体对齐与知识融合

不同来源可能对同一法规、机构或术语使用不同名称。系统通过法规名称与文号去重、别名词表、字符串相似度、向量相似度和人工复核完成实体对齐。对于“民航局”“中国民航局”“中国民用航空局”等机构名称，统一到标准实体，同时保留原始表述。

时效性处理是法律知识融合的核心。系统为法规和条款保存“现行有效、已废止、未生效、已修改、部分失效”等状态，并通过`SUPERSEDES`或修正关系表示版本演进。检索阶段默认优先现行有效条款；对于用户明确询问历史版本的情况，再开放历史条款检索。

### 4.6 图数据库存储

系统使用Neo4j存储实体和关系，并以Cypher作为图查询语言。建图结果包含6650个节点和12489条边，其中包括107个Regulation节点、3522个Article节点、192个Term节点、462个Actor节点、399个Activity节点、983个Sanction节点和531个Case节点。图数据库适合执行条款引用、机型适用、义务主体和违法后果等多跳查询，并可将返回节点直接映射为引用证据。

## 5 GraphRAG检索与问答方法

### 5.1 混合召回

设问题为$q$，条款文档为$d$。稠密检索通过BGE-M3计算问题与条款向量相似度，稀疏检索通过BM25计算词项匹配得分。系统分别获得候选集合，再使用RRF融合排序：

$$
Score(d)=\sum_{r\in R}\frac{1}{k+rank_r(d)}
$$

在参数扫描中，稠密权重为0.9、稀疏权重为0.1时，Hit@5达到0.750、Recall@5达到0.625，优于默认的0.5/0.5配置，说明当前法规语料在表达上高度同质，语义检索对口语化法律问题更有优势。

### 5.2 时效性与效力层级过滤

检索结果不仅按相关度排序，还结合时效性和效力层级进行过滤或加权。默认情况下，已废止条款不作为现行问题的主要依据；未生效标准也不能在当前义务判断中直接替代现行规范。发生冲突时，系统保留法规层级、生效日期、特别法与一般法等元数据，交由规则模块和生成提示词共同处理。

### 5.3 图多跳扩展

对于主召回条款，系统沿以下关系进行一至两跳扩展：

```text
条款 → 引用条款 → 定义或补充义务
条款 → 适用机型 → 相关运行要求
条款 → 义务主体 → 主管机关或申请主体
活动 → 违反后果 → 处罚或责任条款
案例 → 援引法条 → 规范依据
```

图扩展的目的不是简单增加候选数量，而是为生成模型补充结构化关联证据。评测显示，图扩展对主检索Hit@5没有显著提升，但在部分问题中补回了被主检索遗漏的权威条文，说明图扩展的价值主要体现在多条款综合回答和解释完整性方面。

### 5.4 引用约束生成

生成提示词要求模型：

1. 只能依据检索上下文作答；
2. 每个核心结论标注法规名称和条号；
3. 不得把已废止条款作为现行依据；
4. 对检索证据不足的问题明确说明无法确认；
5. 区分法律规定、系统推断和一般性提示；
6. 在答案末尾列出主要条文和关联条款。

输出后进一步进行法规名、条号和来源一致性校验，避免出现引用不存在或引用与结论不对应的问题。

## 6 系统实现

### 6.1 技术栈

| 模块 | 技术实现 |
|---|---|
| 开发语言 | Python |
| 图数据库 | Neo4j Community |
| 向量数据库 | Chroma |
| 稠密嵌入 | BGE-M3 |
| 稀疏检索 | BM25 |
| 重排模型 | bge-reranker-v2-m3 |
| 生成模型 | OpenAI兼容接口，可接入DeepSeek-V3、GLM-4-Flash等 |
| Web服务 | FastAPI + SSE流式输出 |
| 前端 | GPT风格Web界面 |

### 6.2 功能模块

系统按结构化、抽取、建图、案例、向量库、问答和评测划分为七个模块。结构化模块生成统一条款单元；抽取模块生成节点和边；建图模块生成Neo4j导入脚本和图谱导出文件；向量库模块执行父子分块、向量化和BM25索引；问答模块实现检索、图扩展和答案生成；评测模块输出检索层与生成层指标。

### 6.3 分块策略设计与对比

分块（chunking）是决定检索单元粒度的关键一步，直接影响能否把"命中"精确地对齐到一条法律依据。本文实现并对比了两种分块方法。

**方法A：父子分块（parent-child chunking，本文采用）。** 该方法把"用于检索的块"与"喂给生成模型的块"分离：父块（parent）为完整的一条法条或一篇判决摘要，是命中后回溯返回给大语言模型的上下文单元；子块（child）为真正参与索引的更小片段，命中后按`parent_id`回溯其父块。切分尊重法律文本的天然边界——遵循"一条一单元"原则，短法条整条成块不再切碎，带多个款项的长条按款切分，仅对超长条文（超过约525字）才按句末标点做滑动窗口切分（窗口350字、重叠60字）；司法案例以判决摘要为父块、以"标题｜案由＋摘要"为子块，使案由和纠纷类型可被检索。子块的向量化文本统一附加`《法规名》条号`前缀以提升召回，同时保留纯净原文用于展示。关键之处在于`parent_id`与知识图谱节点`id`（法条为`unit_id`、案例为`cli`）对齐，使向量命中可直接跳入Neo4j进行多跳扩展，成为向量侧与图侧的连接点。

**方法B：固定长度滑窗分块（fixed-size sliding window，对照基线）。** 这是朴素RAG最常见的默认切分：把同一部法规的条文按顺序拼接成连续文本流，按固定字数（同样取窗口350字、重叠60字）硬切成等长窗口，**完全不理会法条边界**——一个窗口可以跨越两条条文，一条短法条也可能被相邻条文吞没。为使命中仍能与标注的权威条文比对，每个窗口的归属条款取窗口内占字符最多的那一条（多数归属）。

为公平隔离"分块策略"这一单一变量，两种方法在**同一父文档集合、同一BM25稀疏检索器、同一分词器与领域词典、同一36题标注集及同一评测指标**下对比，仅替换子块切分方式。选择BM25作为固定检索器有三个原因：其一，嵌入模型与重排均不变，指标差异只能来自分块；其二，不调用任何外部Embedding或重排接口，评测零成本且可一键复现；其三，稀疏检索对"块是否与法条边界对齐"最为敏感，最能暴露固定窗口的结构缺陷。

在结构层面，固定窗口分块已暴露出本质问题：全库3522个法条中，仅有1415条曾成为某个窗口的多数归属条款，其余**2107条（59.8%）从未被任何窗口"多数拥有"，在该方案下检索不可达**。这直接源于法律文本条文普遍短小（条文长度中位数约102字），远小于350字的固定窗口，导致多条短法条被挤入同一窗口、只有最长的一条被登记为归属，其余条文的检索信号被淹没。

检索指标对比如表6-1所示（BM25稀疏检索、仅现行有效过滤、每题取top10）。

**表6-1 两种分块方法的检索指标对比**

| 方法 | 子块数 | Hit@3 | Hit@5 | Hit@10 | Recall@5 | Recall@10 | MRR | nDCG@5 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| A 父子分块（本文） | 4837 | 0.333 | 0.389 | 0.528 | 0.250 | 0.389 | 0.269 | 0.188 |
| B 固定窗口分块 | 2394 | 0.250 | 0.389 | 0.389 | 0.208 | 0.250 | 0.174 | 0.126 |

除Hit@5两者持平外，父子分块在其余全部指标上均优于固定窗口分块：Hit@3提升33.3%（0.333对0.250），Hit@10提升35.7%（0.528对0.389），Recall@10提升55.6%（0.389对0.250），MRR提升54.3%（0.269对0.174），nDCG@5提升49.1%（0.188对0.126）。

结果表明固定窗口分块的劣势集中在三方面：一是**排序质量**，MRR和nDCG@5的大幅落后说明即便偶然召回到正确条文，其排名也明显靠后，因为一个跨条窗口混入了相邻条文的词项，稀释了与目标条文的匹配度；二是**召回完整性**，Recall@10落后过半，反映一条法条的答案被切散到多个窗口、或整条被邻条吞没后无法被完整召回；三是**覆盖率**，近六成法条在结构上不可达，意味着大量权威依据从检索空间中先验地缺失。相比之下，父子分块使每一条法条都拥有独立的、边界清晰的检索单元，命中即精确对齐到一条可引用的法律依据，且父块回溯保证了返回给生成模型的上下文是完整的一条条文而非残缺片段。Hit@5的持平进一步说明：在宽松的前5命中口径下两者尚可打平，但一旦考察排序位次、召回完整性与结构覆盖，父子分块的优势便充分显现——这对"依据必须精确到条、且不能遗漏"的法律问答场景尤为关键。综上，本文最终采用父子分块作为系统的分块策略。

### 6.4 前端与引用展示

前端支持hybrid、dense和sparse三种检索模式，支持是否启用重排、图谱扩展和“仅现行有效”过滤。答案下方展示主要条文与知识图谱扩展条款，用户可以查看法规名称、条号、效力状态和原文内容。该设计使模型回答从“黑箱文本”转变为“可核验法律意见参考”。

## 7 实验设计与结果分析

### 7.1 评测集

评测集包含36道问题，覆盖机型分类、实名登记、空域管制、飞行申请、操控资质、适航、罚则、行为规范和特殊活动等13类考点，其中包含6道专门测试时效性和机型混淆的陷阱题。每道题标注权威条款、应避免优先召回的失效条款、应引用法规、关键答案要点和难度类型。

### 7.2 检索层消融实验

| 配置 | Hit@3 | Hit@5 | Recall@5 | MRR | nDCG@5 | Hit@10 |
|---|---:|---:|---:|---:|---:|---:|
| sparse | 0.333 | 0.389 | 0.236 | 0.248 | 0.171 | 0.472 |
| dense | 0.611 | 0.722 | 0.597 | 0.521 | 0.499 | 0.778 |
| hybrid | 0.528 | 0.639 | 0.472 | 0.435 | 0.365 | 0.806 |
| hybrid + rerank | 0.611 | 0.694 | 0.542 | 0.496 | 0.449 | 0.722 |
| hybrid + rerank + expand | 0.611 | 0.694 | 0.542 | 0.498 | 0.449 | 0.722 |

结果表明，纯BM25作为零成本基线效果最低；纯稠密检索的Hit@5最高，说明语义匹配对自然语言提问更有效；混合检索加入重排后，排序质量得到改善；图扩展未直接提高主命中率，但能够在Q20和Q36等问题中补回关联条款。

### 7.3 生成层评测

系统采用hybrid+rerank+expand、alpha=0.9、仅现行有效的配置，生成模型使用DeepSeek-V3，使用独立的Qwen2.5-72B-Instruct作为裁判模型。

| 评价维度 | 平均分 |
|---|---:|
| 忠实度 | 0.889 |
| 正确性 | 0.846 |
| 时效性 | 0.947 |
| 引用正确性 | 0.950 |
| 综合得分 | 0.908 |

36道题中有5道出现幻觉或无充分证据支持的表述。整体上，引用正确性和时效性得分较高，说明来源溯源和现行有效过滤有效；正确性低于引用正确性，说明“引用真实条文”并不等于“完整覆盖问题要点”。

### 7.4 失败案例分析

（1）**实名登记陷阱。** 部分答案受到已废止规定或模型先验影响，对微型无人机是否需要登记作出过度概括；

（2）**标准施行日期错误。** 对国家标准施行时间出现年份偏差，说明日期字段需要更强的结构化校验；

（3）**适航依据不完整。** 个别回答未引用民航法新版条款，反映法规版本排序和权威层级权重仍需优化；

（4）**罚款金额表达错误。** 生成模型可能把不同主体、不同违法情节的罚款区间混合，说明处罚条款应按主体、行为和情节进行细粒度事件建模；

（5）**地方规范依据不足。** 当问题要求具体地方规定时，如果检索上下文缺少对应条款，模型可能使用常识性补全，应改为明确提示证据不足。

## 8 讨论

### 8.1 知识图谱相对纯RAG的价值

纯向量检索能够找到语义相近文本，但不天然表达“哪一条定义了术语”“哪一条规定了罚则”“现行法规取代了哪一部旧法规”等关系。知识图谱为候选条款提供了可解释的结构路径，使系统能够把分散于不同章节、不同法规的依据组织起来。特别是在多跳法律问题中，图扩展可以补充主召回未覆盖的关联条款。

### 8.2 系统局限

第一，评测集规模仍然较小，36道题不能完全代表真实用户分布；第二，图谱中的部分关系由大语言模型抽取，仍需要人工抽样核验；第三，扫描版标准、地方规范和案例材料存在解析质量差异；第四，LLM-as-judge虽然提高了评测效率，但不能完全替代法律专家评审；第五，系统当前主要面向中文文本，对跨区域法规冲突和复杂时间轴的推理能力仍有限。

### 8.3 后续优化方向

（1）建立法律专家参与的分层标注集，增加多法规冲突、历史版本和复杂罚则问题；

（2）对法规效力层级、生效日期和废止关系增加排序特征，将权威性显式加入召回评分；

（3）建设面向“主体—行为—条件—后果”的法律事件图谱，减少罚则混配；

（4）针对国家标准和扫描PDF引入OCR与双人复核流程；

（5）将答案生成改为“先生成结构化结论，再生成自然语言解释”，并对数字、日期、条号和罚款区间进行程序化验证；

（6）评估本地化Embedding和生成模型，降低对外部API的依赖，提高数据安全和可控性。

## 9 结论

本文面向低空经济无人机法律问答场景，设计并实现了一个基于知识图谱增强检索生成的智能问答系统。系统以条款为核心知识单元，构建了包含法规、条款、术语、机型、主体、活动、法律后果和案例的多关系异构知识图谱，并将BGE-M3稠密检索、BM25稀疏检索、重排、Neo4j图扩展及时效性过滤融合到统一问答链路中。

实验结果显示，系统在检索命中、答案忠实度、时效性和引用正确性方面取得了较好效果，综合生成评价达到0.908。研究表明，法律智能问答的关键不只是提升语言模型的生成能力，更在于建设高质量、可追溯、具有时间和效力属性的法律知识底座。与此同时，实名登记、法规版本、日期和罚则金额等问题仍需依靠更严格的版本管理、事件建模和程序化校验。后续工作将继续扩大权威语料规模，完善法律专家评测体系，并提升复杂法规关系推理能力。
