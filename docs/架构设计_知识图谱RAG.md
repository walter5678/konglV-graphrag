# 低空经济无人机法律智能问答系统 —— 基于知识图谱的 RAG 架构设计

> 版本 v0.1 ｜ 2026-07-30
> 目标：在已有「法条 chunk + 结构化元数据」语料之上，构建 **知识图谱增强的 RAG（GraphRAG）** 法律问答系统。
> 相比纯向量 RAG，本方案能处理法律领域特有的**引用、上下位、废止/取代、按机型/场景适用、违规→罚则**等关系型问题。

---

## 0. 为什么用知识图谱（而不只是向量 RAG）

纯向量 RAG 的软肋，恰好是法律问答的高频需求：

| 问题类型 | 纯向量 RAG 表现 | 需要图谱的原因 |
|---|---|---|
| "微型无人机在市区飞要办哪些手续" | 召回零散条文，易漏 | 需按 **机型分类→适用条款** 遍历 |
| "第X条提到的'管制空域'具体指什么" | 术语定义常在另一条 | 需 **条款↔术语定义** 引用跳转 |
| "2017 实名制规定还有效吗" | 可能召回废止旧法 | 需 **废止/取代** 时效关系 |
| "黑飞会受什么处罚" | 罚则与行为分散在不同章 | 需 **行为→罚则条款** 多跳 |
| "这条规定的上位法依据是什么" | 无法表达层级 | 需 **效力层级/立法依据** 关系 |

**核心思路**：向量负责"语义找得到"，图谱负责"关系推得准"。两者融合 = GraphRAG。

## 2. 知识图谱本体设计（Ontology）—— 全案核心

### 2.1 节点类型（实体）

| 节点 | 说明 | 来源 | 关键属性 |
|---|---|---|---|
| `法规` Regulation | 一部法规 | 已有元数据 | 法规名、效力层级、发布机关、文号、公布/生效日期、时效性、来源URL |
| `条款` Article | 一条法条（= 1 个 chunk） | chunks_all.json | 条号、条文、章、节、所属法规、chunk_id |
| `章/节` Section | 结构层级 | 元数据 | 标题、序号 |
| `术语` Term | 法律概念/定义 | LLM抽取 | 术语名、定义、别名 |
| `机型分类` DroneCategory | 微型/轻型/小型/中型/大型 | 领域固定枚举 | 名称、重量/性能阈值 |
| `主体` Actor | 义务/权力主体 | LLM抽取 | 如 操控员、运营人、空管机构、民航局、公安机关 |
| `活动场景` Activity | 行为/场景 | LLM抽取 | 如 实名登记、适航审定、经营性飞行、管制空域飞行 |
| `法律后果` Sanction | 罚则/责任 | LLM抽取 | 罚款额度、责令改正、刑事责任、类型 |

### 2.2 边类型（关系）—— 图谱的价值所在

| 关系 | 方向 | 含义 | 抽取方式 |
|---|---|---|---|
| `属于` BELONGS_TO | 条款→章→法规 | 结构归属 | 元数据直接建 |
| `引用` REFERENCES | 条款→条款 | "依照第X条""见第Y条" | 正则 + LLM |
| `上位法依据` BASED_ON | 下位法→上位法 | 立法依据/授权 | 效力层级 + LLM |
| `废止/取代` SUPERSEDES | 新法→旧法 | 时效关系（⚠️关键） | 人工标注 + LLM |
| `定义` DEFINES | 条款→术语 | 该条给出术语定义 | LLM |
| `适用于` APPLIES_TO | 条款→机型/场景 | 该条约束哪些机型/行为 | LLM |
| `义务主体` OBLIGATES | 条款→主体 | 谁应履行该条 | LLM |
| `违反后果` PENALIZED_BY | 活动/条款→法律后果 | 违规对应罚则 | LLM |
| `修正` AMENDS | 修正案→原条款 | 条文修订 | 人工 + LLM |

> 建议先落地 `属于 / 引用 / 废止取代 / 定义 / 适用于` 五类，覆盖 80% 问答需求；主体、后果作为第二批。

### 2.3 本体图（示意）

```
         上位法依据
   法规 ─────────────► 法规
    │                    ▲
    │属于                │废止/取代
    ▼                    │
   章/节 ── 属于 ──► 条款 ◄── 引用 ── 条款
                     │ │ │
             定义 ───┘ │ └─── 适用于 ──► 机型分类 / 活动场景
              ▼        │义务主体              │
            术语       ▼                    违反后果
                     主体                     ▼
                                          法律后果
```

## 3. 图谱构建流程（Pipeline）

```
raw/chunks_all.json
   │
   ├─[3.1] 结构化关系直接建图（免抽取，高置信）
   │        · 条款──属于──►章/节──属于──►法规
   │        · 法规按效力层级预置上下位骨架
   │
   ├─[3.2] 规则抽取（正则）
   │        · "第X条""第X条第Y款"→ 引用边
   │        · 术语首现"本条例所称XX，是指…"→ 定义边
   │
   ├─[3.3] LLM 抽取（结构化输出，按本体约束 schema）
   │        · 每条 chunk 送 LLM，返回 {术语,主体,适用机型,场景,罚则,引用}
   │        · 强制 JSON schema，落到统一实体表
   │
   ├─[3.4] 实体消歧/归一
   │        · 同义词合并（"民航局"="中国民用航空局"="CAAC"）
   │        · 机型枚举对齐到固定 5 类
   │
   └─[3.5] 写入 Neo4j + 生成向量索引
            · 条款条文 → embedding → 向量索引
            · 实体/关系 → 图节点/边
```

**关键设计：时效性作为一等公民。** 每个法规/条款节点带 `时效性` 与 `生效/失效日期`，检索时默认过滤"已废止"，除非用户显式问历史版本。（对应记忆里的坑：2017 实名制规定已被 GB 46761 取代；民航法须用 2026-07-01 新版。）

## 4. 混合检索策略（Retrieval）

用户问题 → 检索出一个"证据子图 + 相关条文"，喂给 LLM。

```
Query
  │
  ├─[4.1] 意图/实体识别：抽出问题里的 机型、场景、术语、法规名
  │
  ├─[4.2] 向量召回：query embedding → Top-K 条款（语义入口点）
  │
  ├─[4.3] 图谱扩展（多跳遍历，以召回条款为种子）：
  │        · 顺 引用 边 → 拉入被引用条款
  │        · 顺 定义 边 → 拉入术语定义条款
  │        · 顺 适用于 边 → 按问题机型/场景过滤/补全
  │        · 顺 废止取代 边 → 剔除失效条款，替换为现行条款
  │
  ├─[4.4] 时效性 & 效力层级过滤：只留现行有效；冲突时高层级优先
  │
  └─[4.5] 重排（Rerank）：BGE-reranker 对候选条款打分，取 Top-N 进上下文
```

检索模式建议做两档：
- **Local（局部）**：具体条文类问题（"第X条说了什么"）—— 以向量召回为主 + 1~2 跳图扩展。
- **Global（全局）**：概览/流程类问题（"办证全流程")—— 以图谱社区/主题聚合为主（可选，进阶）。

---

## 5. 生成层（Answer + 引用）

- **提示词约束**：只依据检索到的条文回答；每个结论**必须标注**「法规名 + 条号」；找不到依据要明说，不得编造。
- **时效声明**：答案顶部标注所依据法规的生效日期/时效状态。
- **引用溯源**：返回引用条文原文 + 来源URL，供用户核验（法律问答可信度关键）。
- **冲突处理**：多法规冲突时，按 `效力层级 + 新法优于旧法 + 特别法优于一般法` 给出说明。

## 6. 技术选型（建议）

| 层 | 推荐方案 | 备选 | 理由 |
|---|---|---|---|
| 图数据库 | **Neo4j Community**（Cypher + 自带向量索引） | NetworkX(内存,轻量) / NebulaGraph | 成熟、可视化好、5.x 原生向量索引可统一存储；竞赛演示加分 |
| 向量/Embedding | **BGE-M3** 或 bge-large-zh-v1.5（本地,中文强,免费） | 通义/OpenAI embedding | 中文法律文本效果好，无 API 成本 |
| 向量存储 | Neo4j 原生向量索引（统一） | Chroma / FAISS | 图与向量同库，少一个组件 |
| 重排 | bge-reranker-v2-m3 | —— | 显著提升 Top-N 精度 |
| LLM | **DeepSeek-V3** 或 **Qwen2.5**（API/本地） | —— | 中文与法律推理强、便宜；本地可离线演示 |
| 抽取/编排 | LangChain / LlamaIndex 的 GraphRAG 组件，或自研 | —— | 有现成 KG 构建与检索链路 |
| 前端 | Streamlit / Gradio（快速）｜ FastAPI+React（正式） | —— | 竞赛先 Streamlit 出 Demo |

> 竞赛务实路线：数据量（约 2000~3000 条 chunk）不大，**先用 Neo4j + BGE-M3 + DeepSeek API** 跑通，图规模完全够；追求极简可用 NetworkX + Chroma 无外部服务。
