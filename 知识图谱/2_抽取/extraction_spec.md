# 抽取规范（操作化本体）—— Phase2 实体/属性/关系抽取

> 配合 `../ontology.py`（类型骨架）、`vocab.py`（受控词表）。
> 本文件给每个类型补：**定义 / 判定边界 / 正反例 / 抽取方式**，并作为 LLM 抽取的 system prompt 素材。
> 输入：`../1_结构化/out/units_normalized.json`（3701 条款单元）。

## 抽取分层（执行顺序）
| 层 | 边/实体 | 方式 | 置信 | 状态 |
|----|---------|------|------|------|
| ② | `属于` BELONGS_TO | 元数据直接建，免抽取 | 100% | 先做 |
| ③ | `引用` REFERENCES、`定义` DEFINES | 正则为主 | 高 | 次做 |
| ④ | `术语`/`主体`/`机型`/`场景`/`罚则` + `适用于`/`义务主体`/`违反后果` | LLM+schema | 中 | 后做 |
| ⑤ | 归一消歧 | vocab.ALIASES + 机型对齐 | — | 收尾 |

## 一、节点类型（判定边界 + 正反例）

### 法规 Regulation（已有，元数据直接建）
- 一部法规 = 一个 `law_id`。属性取自单元元数据。

### 条款 Article（已有 = 1 单元）
- 一条 = 一个单元 = 一个节点。`unit_id` 为主键。

### 术语 Term　【正则 + LLM】
- **定义**：法条明确给出定义的法律概念。
- **判定**：出现"本条例/本办法所称XX，是指…"、"XX，是指…"、"XX（以下简称YY）"。
- ✅正例：`微型无人驾驶航空器，是指空机重量小于0.25千克…` → Term=微型无人驾驶航空器
- ❌反例：条文里只是提到"无人机"但未定义 → 不建 Term（那是提及，不是定义）

### 机型分类 DroneCategory　【LLM，归入 vocab.DRONE_CATEGORIES 5类】
- **定义**：微/轻/小/中/大 五类固定枚举（+特殊类农用/模型航空器）。
- **判定**：条文提到具体机型或其重量/性能阈值时，归到 5 类之一，**不新造**。
- ✅正例：`小型无人驾驶航空器应当…` → 小型
- ❌反例：泛指"无人驾驶航空器"（未限定机型）→ 不建机型边（是全类适用）

### 主体 Actor　【LLM，归入 vocab.ACTOR_SEEDS 或新增】
- **定义**：承担义务/行使职权的主体。
- ✅正例：`操控员应当…`/`民航局负责…` → Actor=操控员 / 中国民用航空局
- ❌反例：泛称"任何单位和个人" → 记为"任何单位和个人"(通用主体)，不细分

### 活动场景 Activity　【LLM，归入 vocab.ACTIVITY_SEEDS】
- **定义**：受规范约束的行为/场景。
- ✅正例：`从事经营性飞行活动应当取得…` → Activity=经营性飞行/运营合格证
- ❌反例：非行为的描述性内容 → 不建

### 法律后果 Sanction　【LLM，归入 vocab.SANCTION_TYPES】
- **定义**：违规对应的罚则/责任。
- **判定**：出现"处…罚款""责令改正""吊销…""依法追究刑事责任"等。
- ✅正例：`处5万元以上10万元以下罚款` → Sanction{类型:罚款, 额度:5万-10万}
- ❌反例：仅"应当遵守"无罚则 → 不建

## 二、边类型（抽取规则 + 正反例）

### 属于 BELONGS_TO　【元数据，免抽取】
- 条款 →(章/节)→ 法规。直接用单元的 law_id/章/节 建。

### 引用 REFERENCES　【正则】
- **规则**：条文内匹配 `第[一二三…0-9]+条(第X款)?`、`《法规名》第X条`。
- 同法规内 → 指向 `law_id::第X条`；带《法规名》→ 跨法规解析（先建"未解析引用"，消歧阶段对齐 law_id）。
- ✅正例：`依照本条例第十八条第二款…` → REFERENCES→(本law_id::第十八条)
- ❌反例：`第一` 出现在"第一时间"等非条号语境 → 正则须锚定"第X条/款/项"，排除。

### 定义 DEFINES　【正则 + LLM】
- 条款 → 术语。规则：`([^，。]{2,20})，是指` / `所称([^，]{2,20})，是指`。

### 适用于 APPLIES_TO　【LLM】
- 条款 → 机型/场景。该条约束哪些机型或行为。
- ✅正例：`微型、轻型无人驾驶航空器在管制空域飞行的…` → APPLIES_TO→微型、轻型 & 管制空域飞行

### 义务主体 OBLIGATES　【LLM】
- 条款 → 主体。谁应履行该条。

### 违反后果 PENALIZED_BY　【LLM】
- 活动/条款 → 法律后果。

### 上位法依据 BASED_ON / 废止取代 SUPERSEDES / 修正 AMENDS
- BASED_ON：`根据《X法》…制定本条例` → 法规→法规（正则抽"根据《》"+ 效力rank 校验）。
- SUPERSEDES：多靠元数据(时效性=已废止)+人工/LLM；⚠时效关键。
- AMENDS：修正案→原条款，人工+LLM。

## 三、LLM 抽取输出 schema（步骤④，每单元一次调用）
```json
{
  "unit_id": "……",
  "术语": [{"术语名":"", "定义":""}],
  "机型": ["微型","轻型"],              // 只能取 vocab 5类+特殊类
  "主体": ["操控员"],                    // 优先 vocab.ACTOR_SEEDS
  "场景": ["管制空域飞行"],              // 优先 vocab.ACTIVITY_SEEDS
  "罚则": [{"类型":"罚款","额度":"5万-10万","描述":""}],
  "引用": ["第十八条","《民用航空法》第六十一条"]  // 兜底,正则为主
}
```
- **强制 JSON schema**，字段缺省为空数组。机型/主体/场景优先归入受控词表，无法归入才新增并标记。
- 抽完统一过 `vocab.canon()` 归一。
